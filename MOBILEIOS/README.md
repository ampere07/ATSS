# ATSS — iOS customer app

The customer portal from `MOBILEAPP`, as a standalone Expo project for iPhone and iPad.
It contains only what a customer account can reach; staff, technician and agent
features stay in `MOBILEAPP`, which this project does not import from or modify.

## What's in it

| Tab | Screen | Source |
| --- | --- | --- |
| Home | Balance card, Pay Now (Xendit), payment history | `src/pages/DashboardCustomer.tsx` |
| Bills | Statements (PDF), invoices, payment history | `src/pages/Bills.tsx` |
| Support | Latest ticket, ticket details, new ticket with photo | `src/pages/Support.tsx` |
| Menu | Profile, notifications, about, release notes, sign out | `src/pages/Menu.tsx` |

Plus login and forgot password (`src/pages/Login.tsx`), push-token registration,
the Messenger chat button, and the forced-update gate.

Only customer accounts can sign in. A staff login is refused at the login screen,
and a staff session restored from storage is signed out.

## Run

```sh
cd MOBILEIOS/frontend
npm install
cp .env.example .env      # API base URL for local development
npx expo start            # press i for the iOS Simulator (macOS) or scan with a device
```

There is no `ios/` folder in the repo: it is generated by `npx expo prebuild` or by EAS.

Checks that run on any OS:

```sh
npm run typecheck         # tsc --noEmit
npm run bundle:ios        # full Metro + Hermes production bundle for iOS
```

## Build and submit

```sh
npm run build:ios         # eas build --platform ios --profile production
npm run submit:ios        # eas submit --platform ios --profile production
```

`eas submit` reads the App Store Connect key from `./AuthKey_TJ87AS465P.p8`. It is not
committed: copy it into `MOBILEIOS/frontend/` before submitting.

The app uses the same Expo project, bundle id (`com.atss.sync`) and App Store record as
the iOS configuration in `MOBILEAPP`, so push notifications keep working with the
backend's existing Expo tokens and a customer who updates keeps their session.

## Forced updates

`/app-version/config` currently describes the Android release only, and the iOS app
deliberately ignores those fields. To force an iOS update, have the endpoint also return
`ios_min_version` (and optionally `ios_latest_version` and `appstore_url`); without
them the gate stays off. See `src/services/appVersionService.ts`.
